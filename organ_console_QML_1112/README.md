# organ_console_QML — QML 管风琴控制台

这是独立的 QML 界面版本，保留串口控制、实时 MIDI、自动演奏、MIDI 录制和 1..32 位键盘映射能力。界面采用古蓝、天蓝与白色为主色，并以淡绿和淡黄区分状态。

左侧分为六个工作页：控制总览、实时 MIDI、自动演奏、直接控制、键位映射和运行日志。自动演奏页可加载 MIDI/OCF、设置映射范围与聚合窗、转换 MIDI 为 OCF，并查看 OCF 的可读文本解析。

后端 `MainWindow` 已改为纯 `QObject`：只提供属性、信号和 `Q_INVOKABLE` 接口，不再创建任何 QWidget 界面。运行日志页顶部提供「调试回报」开关，状态会同步下位机并持久化。

用 Qt Creator 打开 `organ_console.pro` 可直接构建。命令行构建需要 Qt 5.15+/Qt 6、Qt Quick、Qt Quick Controls 2、Qt Serial Port 和对应的 Qt 编译器；本项目已用 Qt 6.10.1 MinGW 构建验证。MIDI 转 OCF 还需要系统可调用 Python 3。

## 控制器与位图协议

## 本次改动（对齐设计稿）

### 1. 短窗聚合（Qt）
- `KeyStateAggregator`：按键只改 shadow，**默认 4 ms** 窗满后发一张完整位图
- 不再每键一条 `ON/OFF`（多键同时按下合并为 1 次 UART）

### 2. UART 帧
```
@ST,<seq4>,<t_ms8>,<bitmap8>,<crc4>\n
```
- `bitmap`：32 位十六进制，bit0=键1；实际发送哪些位由运行时键位数 N 决定
- CRC16-CCITT-FALSE，覆盖 `ST,seq,t,bitmap`
- 主板成功发 CAN 后回：`@OK,<seq>,0`；失败：`@ERR,<seq>,code`

### 3. CAN 仲裁与单帧广播
| ID | 用途 | 优先级 |
|----|------|--------|
| 0x000 | ALL_OFF | 最高 |
| 0x100 DLC=4 | 键位位图（大端） | 高 |
| 0x100 其它 DLC | DISCOVER/SYNC/SYS | 同 ID 靠 DLC 区分 |
| 0x201+ | 从板上报 | 低（不与键位抢总线） |

载荷示例 `bitmap=0x00000103` → DATA `00 00 01 03`
N1 读 `data[3]`，N2 读 `data[2]`。

### 4. Bus-Off 恢复（主板）
- 使能 TWAI alerts；`INVALID_STATE`/Bus-Off 时 `initiate_recovery` + `twai_start` 并重试发送

## 烧录 / 编译
1. 重新 flash：`can_master`、`can_slave1`、`can_slave2`
2. 重新编译运行 `organ_console.pro`

## 调试
在「运行日志」页打开「调试回报」开关，可看到 `[TX] @ST ...` 与主板 `@OK`/`KEY=...`；开关状态会同步下位机 `DEBUG ON/OFF`，并持久化到设置。

## 键位数 N（1..32）

- 默认 N=16，可在「键位映射」页修改为 1..32；配置和音高表通过 `QSettings` 持久化。
- 默认映射从 MIDI 60（C4）开始连续半音：N=16 时为 60..75，N=32 时为 60..91。
- 修改 N 时保留已有通道映射；新增通道自动在 0..127 内寻找一段连续空闲半音，找不到则拒绝修改。
- 直接控制页按 N 动态生成按钮，每 8 键一块从板：N1=1..8、N2=9..16、N3=17..24、N4=25..32。
- 直接控制键盘最多 32 键：`1–0`、`Q–P`、`A–L`、`Z/X/C`（V 保留不用）。
- 位图发送前统一按 `(1<<N)-1` 掩码；OCF 回放中超出 N 的位会被忽略。
- **固件边界**：当前配套固件只读低 16 位（N1 读 `data[3]`、N2 读 `data[2]`）。N>16 需要主板/从板固件同步读取 `data[1]`（N3）和 `data[0]`（N4）；本仓库不含固件代码。

## MIDI 录制

- 录制来源：外接 MIDI 的原始音高与力度；直接控制按键按当前映射表转成音高（力度 100）。
- 自动演奏和 OCF 回放默认不录，避免重复录音。
- 左侧「MIDI 录制」卡片开始/停止；停止时弹出保存对话框。取消保存时录音保留在内存，可再次保存或丢弃。
- 输出为 SMF Format 0：division=480，tempo=480000 µs/四分音符，即 **1 tick = 1 ms**（125 BPM），录音时长不会因节拍换算漂移。
- 轨道包含 Track Name、Tempo、拍号、自定义 0x7F 元事件（记录 N、映射快照和时间）以及 Note On/Off；停止时会为仍按住的音符补 Note Off。
- 录音中禁止播放、修改映射或修改 N；关闭程序时正在进行的录音会自动保存到默认目录。

## OCF 位图流

自动演奏页可将 MIDI 转为二进制 `.ocf` 文件，也可打开 OCF 播放或查看文本解析结果。

- 默认映射为 MIDI 音高 `60..91`（首尾包含，正好 32 键）；范围外音符忽略。取余模式按范围宽度循环映射。
- 默认聚合窗为 30 ms。事件静默达到窗口后，转换器记录一帧完整的 32 位键状态。
- 输出默认位于输入 MIDI 同级的 `converted` 目录；OCF 含版本、映射、聚合窗、帧时间、位图和 CRC32。
- 转换脚本随 Qt 资源嵌入；运行转换功能需要系统安装 Python 3，并可通过 `python`、`python3` 或 `py -3` 调用。脚本本身不依赖第三方包。
- OCF 帧按文件中的聚合时间直接发送，不会再经过实时短窗聚合。软件位图帧为 32 位，发送前按当前 N 掩码；N>16 的硬件支持仍取决于固件。

OCF v1 使用小端序：24 字节头部依次包含 `OCF1`、版本、位图宽度、映射模式、范围首尾、保留位、聚合窗、总时长和帧数；其后每帧为 64 位毫秒时间戳与 32 位位图，文件尾是覆盖头部和帧数据的 CRC32。位图 bit0 对应目标通道 1。

最小演示文件：`examples/minimal_test.mid`。其默认转换结果是 `examples/converted/minimal_test.ocf`，包含 30 ms 时通道 1 按下，以及 530 ms 时释放。
